# アーキテクチャリファレンスマニュアル

本書はYOSIC-KAPPAのCPU、メモリ、命令の動作を定義します。機器のレジスタは[インターフェース](interface-reference.md)、ソースの書き方は[アセンブラ](assembler.md)、実行手順は[エミュレータ](emulator.md)を参照してください。
原仕様の15命令を維持し、曖昧だったフィールド、FLAGS、リセット、fault、仮想時刻には本実装の補足を適用します。
原仕様は制御レジスタを3本と記していますが、名前があるのはPCとFLAGSだけです。**第3制御レジスタは未定義**で、使える名前や命令を追加していません。

## 1. 数値とCPUの全体像

CPUは整数だけを扱う32ビットのロード／ストア型です。メモリはLRM/SRM、スタックはPSH/POPで読み書きします。
1ビットは0か1、1バイトは8ビット、1ワードは32ビット（4バイト）です。命令はすべて1ワードです。
`0x`付き数値は16進です。bit31が32ビット値の最上位、bit0が最下位です。
メモリでは下位バイトを小さいアドレスへ置きます。例としてワード`0x12345678`は`78 56 34 12`の順です。
32ビット演算の結果は下位32ビットを使います。式中の`mod 2^32`は、2^32で割った余りを意味します。
`signext`は符号拡張です。元の符号ビットを上位へ広げ、たとえば16ビットの`0xFFFF`を32ビットの`0xFFFFFFFF`（-1）にします。

## 2. レジスタとリセット

| 名前 | 幅 | 意味・リセット値 |
|---|---|---|
| R0～R13 | 32ビット | データやアドレス。0 |
| R14 / SP | 32ビット | スタック先頭。0。使用前にRAM内の値を設定する |
| R15 / RZR | 32ビット | 常に0。書込みは捨てる |
| CS | 16ビット | 命令用セグメント。`0x00FF` |
| DS | 16ビット | LRM/SRM用セグメント。0 |
| SS | 16ビット | PSH/POP用セグメント。0 |
| ES | 16ビット | 拡張セグメント。0。現命令にはESを選ぶメモリ命令がない |
| PC | 16ビット | CS内の次の命令位置。0 |
| FLAGS | 16ビット | 演算結果の状態。0 |

RAMも0で初期化します。最初の命令の物理アドレスは`0x00FF0000`です。
RZRを宛先にしても、命令そのものは実行します。算術のFLAGS更新、LRMの機器読出し、POPのSP更新は省略しません。

## 3. 命令の符号化

命令語の区切りは次のとおりです。

| フィールド | ビット | 用途 |
|---|---|---|
| opcode | 31:26 | 命令番号 |
| A | 25:21 | 第1レジスタ、またはLSEGのセグメント番号 |
| B | 20:16 | 第2レジスタ |
| C | 15:11 | 第3レジスタ |
| imm16 | 15:0 | 符号付き即値・メモリ変位 |
| imm21 | 20:0 | 符号付きの相対命令数 |

汎用レジスタのフィールドは5ビットありますが、有効な番号は0～15だけです。
LSEGのAは0=CS、1=DS、2=SS、3=ESです。
次表の「ゼロ必須」は命令語に対するマスクです。`(命令語 & マスク) != 0`なら不正です。
予約ビット、レジスタ番号、opcodeをすべて確認した後に動作を始めます。

| 命令 | opcode | 意味 | 使用フィールド | ゼロ必須 |
|---|---|---|---|---|
| NOP | `0x00` | No OPeration | なし | `0x03FFFFFF` |
| LRM | `0x01` | Load Register from Memory | A=Rd、B=Rb、imm16 | `0` |
| SRM | `0x02` | Store Register to Memory | A=Rs、B=Rb、imm16 | `0` |
| PSH | `0x03` | PuSH register | A=Rs | `0x001FFFFF` |
| SRZ | `0x04` | Skip if Register is Zero | A=Rs | `0x001FFFFF` |
| SNZ | `0x05` | Skip if register is Not Zero | A=Rs | `0x001FFFFF` |
| JMP | `0x06` | JuMP to address | imm21 | `0x03E00000` |
| POP | `0x08` | POP register | A=Rd | `0x001FFFFF` |
| ADD | `0x10` | ADD registers | A=Rd、B=Ra、C=Rb | `0x000007FF` |
| ADI | `0x11` | ADd register Immidiate | A=Rd、B=Ra、imm16 | `0` |
| SUB | `0x12` | SUBtract registers | A=Rd、B=Ra、C=Rb | `0x000007FF` |
| ANL | `0x14` | ANd Logically | A=Rd、B=Ra、C=Rb | `0x000007FF` |
| ORR | `0x15` | OR Registers | A=Rd、B=Ra、C=Rb | `0x000007FF` |
| XOR | `0x16` | eXclusive OR  | A=Rd、B=Ra、C=Rb | `0x000007FF` |
| LSEG | `0x20` | Load SEGment | A=Seg、B=Rs | `0x0000FFFF` |

符号化は`opcode<<26`に使用フィールドをORします。たとえば`ADI R1,RZR,5`は`0x442F0005`、バイト列は`05 00 2F 44`です。

## 全15命令

この節の例は命令単体の意味を示します。実行可能な一式はアセンブラマニュアルにあります。
共通規則として、成功時の次PCは特記がなければ`(旧PC+4) mod 2^16`です。表にないopcode、不正フィールドは`illegal-instruction`になります。
どの命令もfetch時の異常があり得ます。失敗した命令はPC、汎用レジスタ、セグメント、FLAGSを更新しません。

### NOP

構文`NOP`。opcode=`0x00`、他ビットは0です。
計算やデータ転送はしません。FLAGSを保ち、PCは4進みます。例の命令語は`0x00000000`です。共通のfetch/decode異常以外のメモリアクセスはありません。

### LRM

構文`LRM Rd,[Rb+imm]`。opcode=`0x01`、A=Rd、B=Rb、imm16です。
`EA=(Rb+signext(imm16)) mod 2^32`を計算し、DS:EAからワードをRdへ読みます。FLAGSは維持、PCは4進みます。
例`LRM R1,[R2+4]`はR2の4バイト先を読みます。RZR宛でも機器の入力を消費します。
非整列、未割当、方向違反、機器のhandshake違反などはfaultです。

### SRM

構文`SRM Rs,[Rb+imm]`。opcode=`0x02`、A=Rs、B=Rb、imm16です。
LRMと同じEAを計算し、命令開始時のRsをDS:EAへ書きます。FLAGSは維持、PCは4進みます。
例`SRM R1,[R2-4]`はR2の4バイト手前へ書きます。4バイト整列と書込み可能な領域が必要です。ROMへの書込みもfaultです。

### PSH

構文`PSH Rs`。opcode=`0x03`、A=Rs、下位21ビットは0です。
`newSP=(oldSP-4) mod 2^32`を計算し、SS:newSPへ旧Rsを書き、成功後にSPをnewSPへ更新します。FLAGSは維持、PCは4進みます。
例`PSH SP`は減算前のSP値を保存します。書込みfaultならSPは変わりません。

### SRZ

構文`SRZ Rs`。opcode=`0x04`、A=Rs、下位21ビットは0です。
Rs=0ならPCを8進め、違えば4進めます。FLAGSとデータレジスタは維持します。
例`SRZ RZR`は必ず次の1命令を飛ばします。飛ばした命令はfetchしないため、その命令語の不正も検査しません。

### SNZ

構文`SNZ Rs`。opcode=`0x05`、A=Rs、下位21ビットは0です。
Rs≠0ならPCを8進め、0なら4進めます。FLAGSとデータレジスタは維持します。
例`SNZ R1`はR1が非0のときだけ次命令を飛ばします。SRZと同様、飛ばした命令はfetchしません。

### JMP

構文`JMP target`。opcode=`0x06`、Aは0、imm21は符号付き相対命令数です。
CPUの式は`PC=(旧PC+signext(imm21)*4) mod 2^16`です。基準は現在命令で、次命令ではありません。FLAGSは維持します。
例`here: JMP here`の相対値は0、命令語は`0x18000000`です。
アセンブラは同じ64 KiBセグメント内の整列した絶対目的地から差を求めます。CPUのフィールド範囲は-1048576～1048575命令です。分岐後のfetch異常は次の命令で発生します。

### POP

構文`POP Rd`。opcode=`0x08`、A=Rd、下位21ビットは0です。
SS:oldSPからワードを読み、SPを`(oldSP+4) mod 2^32`へ更新してから、Rdへ読んだ値を設定します。FLAGSは維持、PCは4進みます。
例`POP SP`では最終SPがメモリから読んだ値になります。`POP RZR`でもSPは4増えます。読出しfaultなら状態は更新しません。

### ADD

構文`ADD Rd,Ra,Rb`。opcode=`0x10`、A/B/Cを使い、下位11ビットは0です。
`Rd=(Ra+Rb) mod 2^32`。FLAGSのZ/C/N/Vを更新し、PCは4進みます。
例としてRa=`0xFFFFFFFF`、Rb=1なら結果0、Z=1、C=1、N=0、V=0です。算術の桁あふれ自体はfaultにしません。

### ADI

構文`ADI Rd,Ra,imm`。opcode=`0x11`、A/B/imm16を使います。
`Rd=(Ra+signext(imm16)) mod 2^32`。FLAGSの扱いはADDと同じで、PCは4進みます。
例`ADI R1,RZR,-1`は`0xFFFFFFFF`を入れます。即値は-32768～32767です。

### SUB

構文`SUB Rd,Ra,Rb`。opcode=`0x12`、A/B/Cを使い、下位11ビットは0です。
`Rd=(Ra-Rb) mod 2^32`。Z/C/N/Vを更新し、PCは4進みます。
例としてRa=0、Rb=1なら結果`0xFFFFFFFF`、C=0です。C=1は「借りなし」を表します。桁あふれ自体はfaultにしません。

### ANL

構文`ANL Rd,Ra,Rb`。opcode=`0x14`、A/B/Cを使い、下位11ビットは0です。
各ビットのANDをRdへ入れます。Z/Nを更新、C/Vを0にし、PCは4進みます。
例としてRa=`0xF0`、Rb=`0x0F`なら結果0、Z=1です。

### ORR

構文`ORR Rd,Ra,Rb`。opcode=`0x15`、A/B/Cを使い、下位11ビットは0です。
各ビットのORをRdへ入れます。Z/Nを更新、C/Vを0にし、PCは4進みます。
例としてRa=`0xF0`、Rb=`0x0F`なら結果`0xFF`です。

### XOR

構文`XOR Rd,Ra,Rb`。opcode=`0x16`、A/B/Cを使い、下位11ビットは0です。
各ビットの排他的ORをRdへ入れます。Z/Nを更新、C/Vを0にし、PCは4進みます。
例`XOR R1,R1,R1`はR1を0にしてZ=1とします。

### LSEG

構文`LSEG Seg,Rs`。opcode=`0x20`、A=0～3のSeg、B=Rs、下位16ビットは0です。
SegへRsの下位16ビットを入れます。FLAGSは維持、PCは旧PC+4です。
例`LSEG CS,RZR`はCSを0にします。PCを0へ戻す動作ではありません。次のfetchから新CSを使います。新しい場所でのアクセス可否は次のfetchで検査します。

## 4. FLAGSの計算

| ビット | 名前 | 意味 |
|---|---|---|
| 0 | Z | 結果が0なら1 |
| 1 | C | ADD/ADIは桁上がり、SUBは借りなし |
| 2 | N | 結果のbit31 |
| 3 | V | 符号付き計算としての桁あふれ |
| 15:4 | 予約 | 0 |

入力a,b、下位32ビットの結果rを使います。ADIのbは符号拡張済みの32ビット値です。
ADD/ADIのCは32ビットを超える桁上がりです。Vはa,bの符号が同じでrの符号が違う場合に1です。
SUBのCは符号なし比較でa≥bのとき1です。Vはa,bの符号が違い、rの符号がaと違う場合に1です。
論理演算はZ/Nを結果から求め、C/Vを0にします。宛先RZRでも、捨てる前の結果からFLAGSを計算します。

## 5. アドレスとメモリ

物理アドレスは`((segment << 16)+offset) mod 2^32`です。
命令のoffsetは16ビットPC、データとスタックのoffsetは32ビットです。データoffsetを16ビットへ切り詰めません。

| 領域 | 先頭～末尾（両端を含む） | 属性 |
|---|---|---|
| RAM | `0x00000000`～`0x000FFFFF` | 1 MiB、読出し・書込み・実行 |
| コンソールMMIO | `0x00FE0000`～`0x00FE00FF` | 定義した機器レジスタのみ |
| FDC MMIO | `0x00FE0100`～`0x00FE01FF` | 定義した機器レジスタのみ |
| IPL ROM | `0x00FF0000`～`0x00FFFFFF` | 64 KiB、読出し・実行 |

LRM/SRM/PSH/POPは4バイト幅で、4バイト整列が必要です。転送全体が同じ有効領域に収まる必要があります。
32ビットアドレス末端を越える4バイト転送を、0番地へ分割して続けることはしません。
未割当の穴、未定義MMIO、方向違反、ROMへの書込み、領域をまたぐ転送はfaultです。MMIOから命令を実行することもできません。
ROMローダは4～65536バイトの4バイト単位を受け付け、残りを0で埋めます。ROMの拡張子は問いません。

## 6. 境界とfault

PCの通常進行、skip、JMPは16ビットで折り返します。PC=`0xFFFC`の命令はfetchでき、通常の次PCは0です。
PCが非整列ならfetch前に異常とします。SPの加減算は32ビットで折り返しますが、そのアドレスが有効でなければアクセスは失敗します。
バスは4バイト転送を事前検査します。CPUは命令の計算を次状態へ作り、成功したときだけレジスタ、PC、FLAGSを更新します。
機器がすでに受理した副作用まで、後から巻き戻す仕組みではありません。
診断にはPC、問題アドレス、取得できた場合は命令語を表示します。失敗した命令は成功命令数へ数えません。

## 7. 仮想時刻と対象範囲

時計は64ビット符号なし整数のnsです。正常に終わった1命令で1000 ns進みます。faultした命令は時刻を進めません。
命令前に、その時刻までの機器イベントを処理します。命令完了後に進んだ時刻までのイベントも処理します。
同時刻の機器イベントは登録順です。FDCの期限と同時刻にCPUが転送しようとすると、期限イベントが先になります。
過去への登録、時刻の後退、空のcallbackはエラーです。1回の時刻前進で100万件を超えるイベントも診断します。
ホストのsleepや画面の速度には依存しません。1命令ずつ進めても同じ順になります。CPUの実回路のサイクル精度を表す値ではありません。
HALT、バイト命令、専用I/O命令、FPU、割込み受付／復帰命令はありません。IRQは機器の信号として観測します。

## 仕様の根拠と確認範囲

原仕様で定義した命令名、opcode、レジスタ幅を基礎とします。フィールドの役割、予約ビット、算術FLAGS、スタック別名、リセット、メモリ配置、fault、時刻は本実装の確定した補足です。
