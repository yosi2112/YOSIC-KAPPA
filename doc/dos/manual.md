# KAPPA DOS説明書

## 1. 概要と対象

KAPPA DOS Version 0.1はYOSIC-KAPPAの32ビットCPU上で実行するDOSです。ファイル操作とプログラムのディスク読込みは、ゲスト命令からuPD765A互換FDCのMMIOを使って行います。ホストOSにコマンド処理やファイル操作を代行させません。

FAT12、8.3形式の名前、4台のフロッピードライブを扱います。内蔵コマンドは`DIR`、`MKDIR`、`RMDIR`、`DRIVE`、`COPY`、`MOVE`、`DELETE`、`SYS`です。外部実行ファイルには独自ヘッダ`YKE1`と拡張子`.YKE`を使用します。MS-DOSの実行ファイル、x86命令、BATファイル、環境変数、PATH検索、パイプ、リダイレクトには対応していません。

## 2. 起動と保存

DOS起動媒体をドライブ0に接続し、IPLから起動します。エミュレータとIPLを`out/build/`、DOS媒体を`out/dos/`に配置した場合の実行例です。

```powershell
.\out\build\yosic-sim.exe --rom out/build/boot/ipl.rom --disk 0 out/dos/dos.d88 --interactive
```

`KAPPA IPL`、`IPL: BOOT`、`KAPPA DOS Version 0.1`に続いて`0:>`が表示されます。エミュレータは通常Ctrl+Cで停止します。DOSに終了コマンドはありません。

媒体は既定では読取り専用です。ファイル作成・削除やSYS転送を保存する場合、対象ドライブに新しい出力先を指定します。出力先のファイルが既に存在する場合、エミュレータは開始時に拒否します。

```powershell
.\out\build\yosic-sim.exe --rom out/build/boot/ipl.rom --disk 0 out/dos/dos.d88 --disk-copy 0 out/dos/saved.d88 --interactive
```

追加ドライブは`--disk 1 B.d88`、`--disk 2 C.d88`、`--disk 3 D.d88`で接続します。書き込む各ドライブにはそれぞれ`--disk-copy`が必要です。raw `.img`媒体では`--geometry 80 2 18 2`も指定します。エミュレータの詳細は[エミュレータマニュアル](../emulator.md)を参照してください。

## 3. 入力・名前・パス

入力は最大127バイトです。ASCIIの英字はコマンド名・ファイル名で大小文字を区別しません。Enterで実行し、Backspaceで入力を取り消します。長すぎる行は実行せず`Input line too long`、NULを含む行は`Invalid input byte`と表示します。

ファイル名は8文字以内の本体と3文字以内の拡張子からなる8.3形式です。空白を含む名前、長い名前には対応しません。パス区切りは`\`です。ドライブ表記`A:`、`B:`、`C:`、`D:`は番号0、1、2、3に対応します。`DRIVE`とプロンプトだけは番号表記です。

カレントディレクトリを変更するコマンドはありません。相対パスは選択中のドライブのルートを基準にします。`A:\TOOLS\HELLO.YKE`のようにサブディレクトリを指定でき、`.`と`..`はパスの正規化に使えます。正規化後のパスは63文字以内です。

内蔵コマンドの引数を引用符で囲むことはできますが、名前に空白を使用できるようになるわけではありません。`DIR`、`COPY`、`DELETE`は用途に応じて`*`と`?`を受け付けます。詳細は[コマンドリファレンス](commands.md)を参照してください。

## 4. 外部プログラムの起動

```text
0:>HELLO
HELLO YKE
0:>A:\TOOLS\HELLO.YKE argument
```

内蔵コマンドに一致しない入力は、最初のトークンを実行ファイルのパスとして扱います。拡張子を省略すると`.YKE`を補います。明示する拡張子も`.YKE`に限ります。選択中のドライブと指定パスだけを検索し、PATHや他のディレクトリを自動検索しません。最初のトークンを引用符で囲めます。

ファイルの属性・サイズ・FATチェーン、ヘッダ全項目、入口、チェックサムを確認してから実行します。検証エラーや読込み失敗では制御を渡さず、エラーを表示してプロンプトへ戻ります。実行中はDOSのコマンド受付を中断します。プログラムが規約どおり復帰すると、DOSは次の入力を受け付けます。

プログラムは同じCPU・RAM・機器を使用します。メモリ保護、プロセス分離、プリエンプション、faultからの自動復帰はありません。プログラムが無限ループや不正命令を実行した場合、通常のDOS復帰は保証されません。

## 5. 起動ディスクとFAT12

標準の起動媒体は80シリンダ、2ヘッド、18セクタ、512バイト/セクタのフロッピーです。raw形式とD88形式で同じセクタ内容を持ちます。

| LBA | 内容 |
|---|---|
| 0 | IPL用KPB1ヘッダ |
| 1〜16 | 小さなDOSローダー用領域 |
| 17 | 未使用 |
| 18〜145 | DOS本体用領域（最大64 KiB） |
| 146〜161 | 予約領域 |
| 162 | FAT12 BPB |
| 163〜171、172〜180 | FATの2コピー |
| 181〜194 | ルートディレクトリ224項目 |
| 195以降 | データクラスタ（クラスタ2から） |

IPLはKPB1の数値ヘッダ、4〜8192バイト・4バイト整列のpayload、load/entry=`0x2000`、加算チェックサム、セクタ数、reserved=0を確認します。DOSローダーは本体を物理`0x20000`へ読み、チェックサムを確認してCS=2へ移ります。KPB1は起動専用で、外部実行ファイルのYKE1とは別の形式です。

DOSのFAT12処理は512バイト/セクタ、1セクタ/クラスタ、FAT2コピーを前提にします。一般の対応FAT12媒体はLBA0のBPB、KAPPA起動媒体はLBA162のBPBを使用します。FATサイズは1〜9セクタ、ルート項目数は16〜512で16の倍数、媒体全体は2880セクタ以下です。FDCのLBA換算は18セクタ・2ヘッドに固定されています。

外部プログラム読込みはFATチェーン全体を先に検証し、必要セクタ数との一致を確認します。範囲外クラスタ、循環、空き・不良クラスタ、短すぎる・長すぎるチェーンは拒否します。データは各クラスタをFDCで読み、一時領域へリトルエンディアンの32ビット語に再配置します。

## 6. YKE1実行ファイル形式

拡張子は`.YKE`です。ヘッダは24バイト、整数は32ビットのリトルエンディアンです。ヘッダ直後に命令・データからなるpayloadを置きます。末尾に余分なデータを付加しません。

| オフセット | サイズ | 項目 | 条件 |
|---|---|---|---|
| `0x00` | 4 | Magic | ASCII `YKE1`（`59 4B 45 31`） |
| `0x04` | 4 | Version | 1 |
| `0x08` | 4 | PayloadBytes | 4〜65528、4の倍数 |
| `0x0C` | 4 | EntryOffset | payload先頭からのバイト位置、4バイト整列、`0 <= entry < PayloadBytes` |
| `0x10` | 4 | Checksum | payloadをリトルエンディアン32ビット語として加算した下位32ビット |
| `0x14` | 4 | Reserved | 0 |

ファイルサイズは厳密に`24 + PayloadBytes`です。ヘッダのチェックサムにはヘッダ自身を含みません。このチェックサムは破損検出用で、署名や認証ではありません。

payloadは物理`0x80000`へ配置し、CS=8、PC=`EntryOffset`で実行します。コードセグメントの末尾8バイトは遷移ゲートなのでpayloadには含めません。コード内の分岐はCS=8での配置位置に合わせて記述します。入口を0以外にする場合、その位置に配置される命令・分岐を前提にする必要があります。

## 7. 呼出し・復帰規約

| 項目 | プログラム入口での値 |
|---|---|
| CS / PC | 8 / ヘッダのEntryOffset |
| DS / SS / ES | 0 / 0 / 0 |
| SP | `0xF0000`、スタックは下方向に伸長 |
| R1 | `0xF1000`、引数末尾文字列への物理ポインタ |
| R2 | 引数末尾文字列の文字数、終端NULを含まない |
| R3 | カレントドライブ番号0〜3 |
| R4 | 復帰ゲートのセグメント内位置`0xFFF8` |
| その他 | 未規定（依存しないこと） |

引数末尾は最初のトークンとその直後の空白・タブを除いた入力です。大小文字、引用符、途中の空白は保持します。**1文字を1つの32ビット語の下位8ビットに保存**し、ポインタは1文字ごとに4進めます。終端は値0のワードです。DOSは引数を個別に分割しません。

プログラムの終了コードをR0に置き、R5=2としてCS=8の`0xFFF8`へ分岐します。

```asm
        ADI R0,RZR,0       ; exit status
        ADI R5,RZR,2       ; DOS code segment
        JMP 0fff8h
```

復帰ゲートはCSを2へ戻します。DOSはDS/SS/ES、DOS用SP、R6（CR/LF処理）、R10（コンソール）、R11、R12を復元し、FAT・ディレクトリキャッシュを無効化します。R0の終了コードは物理`0x13F00`へ記録します。これを参照する内蔵コマンドや条件付き実行機能はありません。

ゲスト内のRAM使用範囲は次のとおりです。

| 範囲・位置 | 用途 |
|---|---|
| `0x20000`〜`0x2FFFF` | DOSコードと遷移ゲート |
| `0x80000`〜`0x8FFF7` | プログラム領域、ロード前に0クリア |
| `0x8FFF8`〜`0x8FFFF` | 復帰・入口遷移ゲート |
| `0x90000`〜`0xA000F` | 実行ファイルの一時読込み領域 |
| `0xE0000`〜`0xEFFFF` | プログラム用スタックの推奨領域 |
| `0xF1000`〜`0xF11FF` | 引数末尾文字列 |

プログラムはDOSのコード・管理情報や遷移ゲートを破壊しないこと、終了時の分岐までCS=8を維持することが必要です。スタックの推奨範囲は保護・自動検査されません。MMIO、命令の厳密な仕様は[アーキテクチャ](../architecture-reference.md)と[インターフェース](../interface-reference.md)を参照してください。

## 8. ソース構成と検証

| ソース | 責務 |

| [dos.asm](../../src/dos/dos.asm) | 入力・プロンプト・内蔵コマンド優先の振分け |

| [core.inc](../../src/dos/core.inc) | ファイルシステムと内蔵コマンドの正本アセンブリ |
| [core.py](../../src/dos/core.py) | ファイルシステム処理の整数Pythonソースモデル |
| [runtime.inc](../../src/dos/runtime.inc) | ネイティブ関数呼出しと定数展開 |
| [blockio.inc](../../src/dos/blockio.inc) | FDCセクタ転送 |

| [hello.asm](../../src/dos/examples/hello.asm) | 表示・レジスタ変更・終了コード7での復帰例 |

`core.inc`は独立したソース入力として保持します。Pythonモデルからのコンパイラは含まれず、Pythonはゲスト実行時に使いません。YKEローダーの実装正本は`exec.inc`です。

`src/dos/tests/`の統合検証は、実CPU/FDC上で正常実行・復帰、引数保持、分断チェーン、最大サイズ、入口位置、別ドライブ、サブディレクトリ、不正ヘッダ・チェーン・未接続媒体の拒否、8つの内蔵コマンド、SYS転送後の再起動を確認します。
