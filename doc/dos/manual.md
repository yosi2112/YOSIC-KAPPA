# KAPPA DOS説明書

## 1. 概要と対象

KAPPA DOS Version 0.1はYOSIC-KAPPAの32ビットCPU上で実行するDOSです。ファイル操作とプログラムのディスク読込みは、ゲスト命令からuPD765A互換FDCのMMIOを使って行います。ホストOSにコマンド処理やファイル操作を代行させません。

FAT12、8.3形式の名前、4台のフロッピードライブを扱います。内蔵コマンドは`DIR`、`MKDIR`、`RMDIR`、`DRIVE`、`COPY`、`MOVE`、`DELETE`、`SYS`です。外部実行ファイルには独自ヘッダ`YKE1`と拡張子`.YKE`を使用します。MS-DOSの実行ファイル、x86命令、BATファイル、環境変数、PATH検索、パイプ、リダイレクトには対応していません。

## 2. 起動と保存

DOS起動媒体をドライブ0に接続し、IPLから起動します。エミュレータとIPLを`out/build/`、DOS媒体を`out/dos/`に配置した場合の実行例です。

```powershell
.\out\build\yosic-sim.exe --rom out/build/boot/ipl.rom --disk 0 out/dos/dos.d88 --interactive
```

`KAPPA IPL`、`IPL: BOOT`、`KAPPA DOS Version 0.1`に続いて`0:>`が表示されます。エミュレータは通常Ctrl+Cで停止します。DOSに終了コマンドはありません。

媒体は既定では読取り専用です。ファイル作成・削除やSYS転送を保存する場合、対象ドライブに新しい出力先を指定します。出力先のファイルが既に存在する場合、エミュレータは開始時に拒否します。

```powershell
.\out\build\yosic-sim.exe --rom out/build/boot/ipl.rom --disk 0 out/dos/dos.d88 --disk-copy 0 out/dos/saved.d88 --interactive
```

追加ドライブは`--disk 1 B.d88`、`--disk 2 C.d88`、`--disk 3 D.d88`で接続します。書き込む各ドライブにはそれぞれ`--disk-copy`が必要です。raw `.img`媒体では`--geometry 80 2 18 2`も指定します。エミュレータの詳細は[エミュレータマニュアル](../emulator.md)を参照してください。

## 3. 入力・名前・パス

入力は最大127バイトです。ASCIIの英字はコマンド名・ファイル名で大小文字を区別しません。Enterで実行し、Backspaceで入力を取り消します。長すぎる行は実行せず`Input line too long`、NULを含む行は`Invalid input byte`と表示します。

ファイル名は8文字以内の本体と3文字以内の拡張子からなる8.3形式です。空白を含む名前、長い名前には対応しません。パス区切りは`\`です。パスのドライブ表記は`0:`、`1:`、`2:`、`3:`です。プロンプト、`DRIVE`、パスで同じドライブ番号を使用します。英字のドライブ表記は受け付けません。

カレントディレクトリを変更するコマンドはありません。相対パスは選択中のドライブのルートを基準にします。`1:\TOOLS\HELLO.YKE`のようにサブディレクトリを指定でき、`.`と`..`はパスの正規化に使えます。正規化後のパスは63文字以内です。

内蔵コマンドの引数を引用符で囲むことはできますが、名前に空白を使用できるようになるわけではありません。`DIR`、`COPY`、`DELETE`は用途に応じて`*`と`?`を受け付けます。詳細は[コマンドリファレンス](commands.md)を参照してください。

## 4. 外部プログラムの起動

```text
0:>HELLO
HELLO YKE
0:>1:\TOOLS\HELLO.YKE argument
```

内蔵コマンドに一致しない入力は、最初のトークンを実行ファイルのパスとして扱います。拡張子を省略すると`.YKE`を補います。明示する拡張子も`.YKE`に限ります。選択中のドライブと指定パスだけを検索し、PATHや他のディレクトリを自動検索しません。最初のトークンを引用符で囲めます。

ファイルの属性・サイズ・FATチェーン、ヘッダ全項目、入口、チェックサムを確認してから実行します。検証エラーや読込み失敗では制御を渡さず、エラーを表示してプロンプトへ戻ります。実行中はDOSのコマンド受付を中断します。プログラムが規約どおり復帰すると、DOSは次の入力を受け付けます。

プログラムは同じCPU・RAM・機器を使用します。メモリ保護、プロセス分離、プリエンプション、faultからの自動復帰はありません。プログラムが無限ループや不正命令を実行した場合、通常のDOS復帰は保証されません。

## 5. 起動ディスクとFAT12

標準の起動媒体は80シリンダ、2ヘッド、18セクタ、512バイト/セクタのフロッピーです。raw形式とD88形式で同じセクタ内容を持ちます。

| LBA | 内容 |
|---|---|
| 0 | IPL用KPB1ヘッダ |
| 1〜16 | 小さなDOSローダー用領域 |
| 17 | 未使用 |
| 18〜145 | DOS本体用領域（最大64 KiB） |
| 146〜161 | 予約領域 |
| 162 | FAT12 BPB |
| 163〜171、172〜180 | FATの2コピー |
| 181〜194 | ルートディレクトリ224項目 |
| 195以降 | データクラスタ（クラスタ2から） |

IPLはKPB1の数値ヘッダ、4〜8192バイト・4バイト整列のpayload、load/entry=`0x2000`、加算チェックサム、セクタ数、reserved=0を確認します。DOSローダーは本体を物理`0x20000`へ読み、チェックサムを確認してCS=2へ移ります。KPB1は起動専用で、外部実行ファイルのYKE1とは別の形式です。

DOSのFAT12処理は512バイト/セクタ、1セクタ/クラスタ、FAT2コピーを前提にします。一般の対応FAT12媒体はLBA0のBPB、KAPPA起動媒体はLBA162のBPBを使用します。FATサイズは1〜9セクタ、ルート項目数は16〜512で16の倍数、媒体全体は2880セクタ以下です。FDCのLBA換算は18セクタ・2ヘッドに固定されています。

外部プログラム読込みはFATチェーン全体を先に検証し、必要セクタ数との一致を確認します。範囲外クラスタ、循環、空き・不良クラスタ、短すぎる・長すぎるチェーンは拒否します。データは各クラスタをFDCで読み、一時領域へリトルエンディアンの32ビット語に再配置します。

## 6. YKE1実行ファイル形式

拡張子は`.YKE`です。ヘッダは24バイト、整数は32ビットのリトルエンディアンです。ヘッダ直後に命令・データからなるpayloadを置きます。末尾に余分なデータを付加しません。

| オフセット | サイズ | 項目 | 条件 |
|---|---|---|---|
| `0x00` | 4 | Magic | ASCII `YKE1`（`59 4B 45 31`） |
| `0x04` | 4 | Version | 1 |
| `0x08` | 4 | PayloadBytes | 4〜65520、4の倍数 |
| `0x0C` | 4 | EntryOffset | payload先頭からのバイト位置、4バイト整列、`0 <= entry < PayloadBytes` |
| `0x10` | 4 | Checksum | payloadをリトルエンディアン32ビット語として加算した下位32ビット |
| `0x14` | 4 | Reserved | 0 |

ファイルサイズは厳密に`24 + PayloadBytes`です。ヘッダのチェックサムにはヘッダ自身を含みません。このチェックサムは破損検出用で、署名や認証ではありません。

payloadは物理`0x80000`へ配置し、CS=8、PC=`EntryOffset`で実行します。コードセグメントの末尾16バイトはシステムコール・復帰・入口遷移ゲートなのでpayloadには含めません。コード内の分岐はCS=8での配置位置に合わせて記述します。入口を0以外にする場合、その位置に配置される命令・分岐を前提にする必要があります。システムコール追加前の上限65528バイトから65520バイトに変更されており、新上限を超える旧YKEファイルは再作成が必要です。

## 7. 呼出し・復帰規約

| 項目 | プログラム入口での値 |
|---|---|
| CS / PC | 8 / ヘッダのEntryOffset |
| DS / SS / ES | 0 / 0 / 0 |
| SP | `0xF0000`、スタックは下方向に伸長 |
| R1 | `0xF1000`、引数末尾文字列への物理ポインタ |
| R2 | 引数末尾文字列の文字数、終端NULを含まない |
| R3 | カレントドライブ番号0〜3 |
| R4 | 復帰ゲートのセグメント内位置`0xFFF8` |
| その他 | 未規定（依存しないこと） |

引数末尾は最初のトークンとその直後の空白・タブを除いた入力です。大小文字、引用符、途中の空白は保持します。**1文字を1つの32ビット語の下位8ビットに保存**し、ポインタは1文字ごとに4進めます。終端は値0のワードです。DOSは引数を個別に分割しません。

従来の終了規約ではプログラムの終了コードをR0に置き、R5=2としてCS=8の`0xFFF8`へ分岐します。この規約は引き続き使用できます。新しいプログラムは次章の`EXIT`システムコールでも終了できます。

```asm
        ADI R0,RZR,0       ; exit status
        ADI R5,RZR,2       ; DOS code segment
        JMP 0fff8h
```

復帰ゲートはCSを2へ戻します。DOSはDS/SS/ES、DOS用SP、R6（CR/LF処理）、R10（コンソール）、R11、R12を復元し、FAT・ディレクトリキャッシュを無効化します。R0の終了コードは物理`0x13F00`へ記録します。これを参照する内蔵コマンドや条件付き実行機能はありません。

ゲスト内のRAM使用範囲は次のとおりです。

| 範囲・位置 | 用途 |
|---|---|
| `0x20000`〜`0x2FFFF` | DOSコードと遷移ゲート |
| `0x80000`〜`0x8FFEF` | プログラム領域、ロード前に0クリア |
| `0x8FFF0`〜`0x8FFFF` | システムコール・復帰・入口遷移ゲート |
| `0x90000`〜`0xA000F` | 実行ファイルの一時読込み領域 |
| `0xD0000`〜`0xDFFFF` | プログラム用の作業領域、起動時の内容は未規定 |
| `0xE0000`〜`0xEFFFF` | プログラム用スタックの推奨領域 |
| `0xF1000`〜`0xF11FF` | 引数末尾文字列 |

プログラムはDOSのコード・管理情報や遷移ゲートを破壊しないこと、終了時の分岐までCS=8を維持することが必要です。スタックの推奨範囲は保護・自動検査されません。MMIO、命令の厳密な仕様は[アーキテクチャ](../architecture-reference.md)と[インターフェース](../interface-reference.md)を参照してください。

## 8. システムコール

### 呼出しと復帰

アプリは**R1にファンクション番号、R2に引数、R7に復帰先を設定し、`JMP 0fff0h`でDOSを呼び出します**。ゲートがCSを2へ切り替え、DOSが処理を実行します。`EXIT`以外はCS=8へ戻り、R7で指定した位置からアプリを再開します。CPU命令やホスト側の特別な処理は追加していません。

| レジスタ | 規約 |
|---|---|
| R1 | ファンクション番号。復帰時も保持 |
| R2 | 引数、または結果。用途は下表を参照 |
| R7 | アプリのセグメント内復帰位置。4バイト整列、`0 <= R7 < PayloadBytes` |
| R0 | 結果コード。0=成功、非0=エラー。`EXIT`では終了コードをR2に指定 |
| R3、R4、R6〜R13、SP | 呼出し前の値を保持。R7も保持 |
| R5 | ゲートが使用。通常復帰後は8 |
| CS / DS / SS / ES | 通常復帰後は8 / 0 / 0 / 0 |
| FLAGS | 未規定 |

R7は物理アドレスではなく、コード内のラベルの位置です。入口が0以外の場合も、入口からの相対位置ではなくセグメント先頭からの位置を指定します。不正なR7は復帰できないため、アプリを終了コード87で終了してDOSへ戻します。`EXIT`ではR7を検査せず、復帰先は不要です。

### ファンクション一覧

| R1 | 名前 | R2の入力 | R2の出力・動作 |
|---|---|---|---|
| `00h` | EXIT | 32ビット終了コード | DOSへ終了。アプリには戻らない |
| `01h` | PUTCHAR | 文字コード0〜255 | 1文字出力。R2を保持 |
| `02h` | PUTS | NUL終端文字列の物理ポインタ | 文字列出力。最大4095文字。R2を保持 |
| `03h` | GETCHAR | 不使用 | 入力があれば文字コード0〜255、なければ`0xFFFFFFFF`。待機・エコーはしない |
| `04h` | GETDRIVE | 不使用 | カレントドライブ番号0〜3 |
| `05h` | SETDRIVE | ドライブ番号0〜3 | 媒体を確認して選択を変更。失敗時は元のドライブを維持。R2を保持 |
| `10h` | DIR | 内蔵DIRの引数文字列への物理ポインタ | 一覧表示。R2を保持 |
| `11h` | MKDIR | 内蔵MKDIRの引数文字列への物理ポインタ | ディレクトリ作成。R2を保持 |
| `12h` | RMDIR | 内蔵RMDIRの引数文字列への物理ポインタ | 空ディレクトリ削除。R2を保持 |
| `13h` | COPY | 内蔵COPYの引数文字列への物理ポインタ | ファイルコピー。R2を保持 |
| `14h` | MOVE | 内蔵MOVEの引数文字列への物理ポインタ | 移動・名前変更。R2を保持 |
| `15h` | DELETE | 内蔵DELETEの引数文字列への物理ポインタ | ファイル削除。R2を保持 |
| `16h` | SYS | 内蔵SYSの引数文字列への物理ポインタ | ドライブ0から起動システム転送。R2を保持 |

ファイル操作の文字列にはコマンド名を含めません。たとえばCOPYには`0:\SOURCE.DAT 1:\COPY.DAT /Y`、SYSには`1:`を渡します。最大127文字、末尾NULが必要です。空文字列や`/?`も内蔵コマンドと同じ意味です。引用符、ワイルドカード、確認入力、エラー表示も[コマンドリファレンス](commands.md)の規則に従います。これらは内蔵操作の呼出し口であり、ファイルハンドルを用いたopen/read/write機能はありません。

GETCHARは入力待ちをしません。未入力とEOFはいずれも`0xFFFFFFFF`を返し、R0は0です。EnterのCR/LFもそのまま返します。ファイル操作の確認入力は、従来の内蔵コマンドと同じく入力を待つ場合があります。

### ポインタと結果コード

文字列は引数末尾と同じ形式です。**1文字を1つの32ビット語に保存**し、その値は0〜255、終端は値0のワードです。通常のバイト配列とは異なり、ポインタは1文字ごとに4進めます。

ポインタは4バイト整列の物理アドレスです。文字列全体と終端は、次のいずれか1つの範囲に収めてください。DOSは範囲・文字値・最大長・終端を検証してから処理し、不正な文字列を途中まで出力しません。

| 範囲 | 使用可能な文字列領域 |
|---|---|
| `0x80000`〜`0x8FFEF` | アプリのコード・データ領域 |
| `0xD0000`〜`0xEFFFF` | アプリの作業領域・スタック領域 |
| `0xF1000`〜`0xF11FF` | 起動時の引数末尾領域 |

| R0 | 意味 |
|---|---|
| 0 | 成功 |
| 1 | 未定義のファンクション番号 |
| 87 | 不正な引数、ポインタ、文字値、終端または最大長 |
| その他 | ファイル操作・媒体のエラーコード。[コマンドのメッセージ一覧](commands.md#主なメッセージ)を参照 |

通常のシステムコール結果はR0で確認します。物理`0x13F00`への終了コード記録はアプリ終了時に行います。システムコールは同期的で、再入には対応しません。メモリ保護があるわけではないため、アプリはDOS管理領域とゲートを書き換えてはいけません。

### 呼出し例

[`api.inc`](../../src/dos/api.inc)には番号定数、32ビット定数を設定する`DosConst`、R1とR7を設定してJMPする`DosCall`マクロを用意しています。明示的な呼出しは次の形です。`api.inc`をINCLUDEしたアプリ内に記述します。

```asm
        ADI R1,RZR,DOS_PUTS      ; ファンクション番号02h
        DosConst R2,80000h+message ; 文字列の物理ポインタ
        DosConst R7,resume       ; CS=8内の復帰位置
        JMP 0fff0h
resume:
        SRZ R0                  ; 成功なら次のJMPを飛ばす
        JMP failed
        ADI R2,RZR,0
        DosCall DOS_EXIT
failed:
        ADD R2,R0,RZR
        DosCall DOS_EXIT
message:
        DD 72,69,76,76,79,13,10,0
```

[`syscall.asm`](../../src/dos/examples/syscall.asm)はシステムコールだけで表示と終了を行う実行例です。`DosCall`で復帰先を設定するため、連続した呼出しでも同じ記述を使用できます。

`core.inc`は独立したソース入力として保持します。Pythonモデルからのコンパイラは含まれず、Pythonはゲスト実行時に使いません。YKEローダーの実装正本は`exec.inc`です。

`src/dos/tests/`の統合検証は、実CPU/FDC上で正常実行・復帰、引数保持、分断チェーン、最大サイズ、入口位置、別ドライブ、サブディレクトリ、不正ヘッダ・チェーン・未接続媒体の拒否、8つの内蔵コマンド、SYS転送後の再起動を確認します。`verify-syscall.py`では13ファンクション、レジスタ・スタック保持、ポインタ・復帰位置の検証、文字入力とEOF、ファイル操作とシステム転送も確認します。
